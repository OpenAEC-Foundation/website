Y-app — De Everything-app voor je bedrijf

La Everything-app para tu empresa: correo, ERP, facturas, registro de horas, proyectos, comunicación y mucho más en una sola herramienta. Multi-tenant: una cuenta, varias instancias de ERPNext.

Beta Everything-app y-app.impertio.app →
React 19 + TypeScript + Vite 7 · Node.js 20 + Express · ERPNext + NextCloud + Office 365 · AES-256-GCM credential vault

¿Qué es Y-app?

Y-app no es una herramienta de chat ni un frontend de ERP independiente. Es una "Everything-app": un espacio de trabajo multi-tenant de ERPNext que reúne toda la pila de tu empresa en una sola aplicación web. Correo (IMAP/SMTP + Office 365), ERP (ERPNext), archivos (NextCloud), chat (Teams, NextCloud Talk, Telegram), calendario, un asistente de IA (Claude) y decenas de módulos de negocio, todo accesible desde una sola pestaña del navegador.

  • Multi-tenant — conecta varias instancias de ERPNext a una sola cuenta de Y-app
  • Bóveda cifrada — credenciales en una base de datos SQLite del lado del servidor con AES-256-GCM y PBKDF2-SHA256 (210 000 iteraciones)
  • Sin pestañas del navegador — cambia entre instancias mediante pestañas dentro de la app, cada una con su propio enrutamiento y sesión
  • Modo empleador o empleado — restringe módulos por instancia mediante un desplegable
  • i18n completa NL/EN — más de 1190 traducciones, conmutables en tiempo de ejecución

Cómo funciona

Y-app se ejecuta en tu propio servidor (o a través de impertio.app). El autorregistro, la gestión de instancias y el cambio de modo se hacen dentro de la app, sin tickets de TI.

1

Crea una cuenta de Y-app

Autorregistro con correo y contraseña. Bcrypt con 12 rondas, cookies de sesión HttpOnly y caché de credenciales limitada a la sesión.

2

Añade instancias de ERPNext

Para cada empresa o cliente: URL, nombre, color y credenciales. Se cifran de inmediato en la bóveda del lado del servidor.

3

Cambia mediante pestañas en la app

Sin pestañas del navegador: cambia entre instancias dentro de Y-app. Cada pestaña conserva su propio estado de enrutamiento, sesión de ERPNext y caché.

4

Modo empleador o empleado

Cambia por instancia entre el conjunto completo de módulos (empleador) o un conjunto restringido para el personal (empleado).

Multi-tenant y cifrado: ni siquiera el host puede leer tus credenciales

Y-app funciona con un principio de conocimiento cero para tus credenciales de ERPNext. Cada combinación de correo, clave de ERPNext y token OAuth2 se cifra en una bóveda SQLite del lado del servidor con una clave maestra que solo puede descifrarse con tu contraseña de Y-app.

  • AES-256-GCM — cifrado autenticado para cada credencial
  • PBKDF2-SHA256, 210 000 iteraciones — la recomendación actual de OWASP para la derivación de claves
  • Archivo de clave maestra con modo 600 — legible únicamente por el proceso de Y-app
  • AsyncLocalStorage por petición — las credenciales nunca se comparten entre usuarios dentro del mismo proceso de Node
  • Ni siquiera el host puede ver tus datos — sin tu inicio de sesión, la bóveda es un blob de bytes aleatorios
  • Una cuenta, varias empresas — ideal para asesorías, consultores, holdings y organizaciones de franquicia

¿Qué incluye? — los módulos

Y-app reúne decenas de módulos en siete dominios. Cada módulo se conecta directamente a la instancia activa de ERPNext: sin inicios de sesión separados, sin URL separadas.

Tecnología

React 19 TypeScript Vite 7 TailwindCSS 4 react-router-dom 7 react-i18next Node.js 20+ Express 4 WebSocket (ws) better-sqlite3 bcryptjs (12 rounds) AES-256-GCM PBKDF2-SHA256 (210k) AsyncLocalStorage SQLite (WAL) Leaflet + react-leaflet xterm.js PM2 tsx --watch nginx

React 19 + TypeScript + Vite 7 + TailwindCSS 4 en el frontend, Node.js 20 + Express 4 + WebSocket en el backend. Autenticación mediante bcryptjs (12 rondas), cookies HttpOnly y AsyncLocalStorage para el aislamiento de credenciales por petición. Cifrado con AES-256-GCM y PBKDF2-SHA256 (210 000 iteraciones), datos en una base de datos SQLite (modo WAL). En producción se ejecuta bajo PM2, detrás de un proxy inverso nginx con terminación TLS, actualización a WebSocket y servido estático de dist. Desarrollo mediante tsx --watch.
