APIs

Every tool as an API

You can call every tool on the SuperCloud from your own software as well: calculate, convert, check and store. With one key, in one open language (IFCX), and you pay for what you use.

  • One key for every tool

    You create API keys in the admin environment, per environment and with only the permissions needed. The same key works for every tool.

  • IFCX in, IFCX out

    The APIs speak the same open language as the apps. A model you send to the heat loss calculation goes straight on to the energy calculation without conversion.

  • Pay for what you use

    Calls count towards your environment's usage, at cost plus 10%. You set your own limits.

What a call looks like

A heat loss calculation from your own script: send an IFCX model and get the result per room back.

Illustrative example; the final specification will follow per tool.

curl -X POST https://api.cloud.open-aec.com/v1/heatloss/calculations \
  -H "Authorization: Bearer $OPENAEC_API_KEY" \
  -H "Content-Type: application/json" \
  --data @woning.ifcx

# antwoord
{
  "status": "done",
  "standard": "ISSO 51",
  "rooms": 12,
  "design_heat_loss_w": 6420,
  "result": "woning-warmteverlies.ifcx"
}

How it works

  • Signing inAPI keys for scripts and integrations; OAuth for apps acting on behalf of a user.
  • SpecificationA public OpenAPI specification per tool, with examples.
  • LimitsLimits per key and per environment, so one script cannot overload your environment.
  • In the EUCalls are processed in the EU, with the same security as the apps themselves.
