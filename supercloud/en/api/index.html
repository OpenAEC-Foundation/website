APIs

Every tool as an API

Every tool on the SuperCloud can also be called from your own software, to calculate, convert, check and store. You use one key and one open language (IFCX), and pay for what you use.

  • One key for every tool

    You create API keys in the admin environment, per environment and with only the permissions needed. The same key works for every tool.

  • IFCX as input and output

    The APIs use the same open language as the apps. A model you send to the heat loss calculation passes on to the energy calculation without conversion.

  • Pay for what you use

    Calls count towards your environment's usage. You set your own limits.

An example call

A heat loss calculation from your own script: you send an IFCX model and receive the result per room.

Illustrative example; the final specification will follow per tool.

curl -X POST https://demo.cloud.open-aec.eu/api/v1/heatloss/calculations \
  -H "Authorization: Bearer $OPENAEC_API_KEY" \
  -H "Content-Type: application/json" \
  --data @woning.ifcx

# antwoord
{
  "status": "done",
  "standard": "ISSO 51",
  "rooms": 12,
  "design_heat_loss_w": 6420,
  "result": "woning-warmteverlies.ifcx"
}

How it works

  • AuthenticationAPI keys for scripts and integrations; OAuth for apps acting on behalf of a user.
  • SpecificationA public OpenAPI specification per tool, with examples.
  • LimitsLimits per key and per environment, so one script cannot overload your environment.
  • In the EUCalls are processed in the EU, with the same security as the apps themselves.
