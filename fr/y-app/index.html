Y-app

L'Everything-app pour votre entreprise — e-mail, ERP, factures, feuilles de temps, projets, communication et plus encore dans un seul outil. Multi-tenant : un compte, plusieurs instances ERPNext.

Démo en direct Dépôt GitHub
Beta Everything-app Multi-tenant AES-256-GCM

Comment ça fonctionne

Y-app tourne sur votre propre serveur (ou via impertio.app). L'inscription autonome, la gestion des instances et le changement de mode se font entièrement dans l'application — pas besoin de ticket IT.

1

Créez un compte Y-app

Inscription autonome avec e-mail et mot de passe. Bcrypt à 12 rounds, cookies de session HttpOnly, cache d'identifiants limité à la session.

2

Ajoutez des instances ERPNext

Pour chaque entreprise ou client : URL, nom, couleur et identifiants. Chiffrés immédiatement dans le coffre-fort côté serveur.

3

Basculez via les onglets internes

Pas d'onglets de navigateur : basculez entre les instances directement dans Y-app. Chaque onglet conserve son propre état de routage, sa session ERPNext et son cache.

4

Mode employeur ou employé

Basculez par instance entre l'ensemble complet des modules (Employeur) ou un ensemble restreint pour le personnel (Employé).

Everything-app

Qu'est-ce que Y-app ?

Y-app n'est ni un outil de chat ni un frontend ERP autonome. C'est une « Everything-app » — un espace de travail ERPNext multi-tenant qui regroupe toute votre pile métier dans une seule application web. E-mail (IMAP/SMTP + Office 365), ERP (ERPNext), fichiers (NextCloud), chat (Teams, NextCloud Talk, Telegram), agenda, un assistant IA (Claude) et des dizaines de modules métier — tous accessibles depuis un seul onglet de navigateur.

  • Multi-tenant Connectez plusieurs instances ERPNext à un seul compte Y-app

  • Coffre-fort chiffré Identifiants stockés côté serveur dans une base SQLite avec AES-256-GCM, PBKDF2-SHA256 (210k itérations)

  • Pas besoin d'onglets de navigateur Basculez entre les instances via des onglets internes à l'application, chacun avec son propre routage et sa propre session

  • Mode employeur ou employé Restreignez les modules par instance via un menu déroulant

  • i18n complète NL/EN Plus de 1190 traductions, modifiables à la volée

Qu'y a-t-il à l'intérieur ? — les modules

Y-app regroupe des dizaines de modules répartis sur sept domaines. Chaque module est connecté directement à l'instance ERPNext active — pas de connexions séparées, pas d'URL séparées.

Zero-knowledge

Multi-tenant et chiffré — même l'hébergeur ne peut pas lire vos identifiants

Y-app applique un principe zero-knowledge pour vos identifiants ERPNext. Chaque combinaison d'e-mail, de clé ERPNext et de jeton OAuth2 est chiffrée dans un coffre-fort SQLite côté serveur avec une clé maître qui ne peut être déchiffrée qu'avec votre mot de passe Y-app.

  • AES-256-GCM Chiffrement authentifié pour chaque identifiant

  • PBKDF2-SHA256, 210 000 itérations La recommandation OWASP actuelle pour la dérivation de clé

  • Fichier de clé maître en mode 600 Lisible uniquement par le processus Y-app

  • AsyncLocalStorage par requête Les identifiants ne sont jamais partagés entre utilisateurs au sein d'un même processus Node

  • Même l'hébergeur ne voit pas vos données Sans votre identifiant de connexion, le coffre-fort n'est qu'un bloc d'octets aléatoires

  • Un seul compte, plusieurs entreprises Idéal pour les comptables, consultants, holdings et organisations en franchise

Technologie

React 19 TypeScript Vite 7 TailwindCSS 4 react-router-dom 7 react-i18next Node.js 20+ Express 4 WebSocket (ws) better-sqlite3 bcryptjs (12 rounds) AES-256-GCM PBKDF2-SHA256 (210k) AsyncLocalStorage SQLite (WAL) Leaflet + react-leaflet xterm.js PM2 tsx --watch nginx

React 19 + TypeScript + Vite 7 + TailwindCSS 4 côté frontend, Node.js 20 + Express 4 + WebSocket côté backend. Authentification via bcryptjs (12 rounds), cookies HttpOnly et AsyncLocalStorage pour l'isolation des identifiants par requête. Chiffrement avec AES-256-GCM et PBKDF2-SHA256 (210k itérations), données dans une base SQLite (mode WAL). La production tourne sous PM2, derrière un reverse proxy nginx avec terminaison TLS, upgrade WebSocket et service des fichiers statiques dist. Développement via tsx --watch.
