01 Planification

Voyez ce qui fixe votre date de fin

L'application calcule le chemin critique, la marge et les tâches quasi critiques. Plusieurs chemins critiques et les échéances manquées apparaissent tout de suite dans le Gantt.

Ouvrez vos fichiers MS Project et Primavera P6

Questions fréquentes

Puis-je ouvrir des fichiers de Microsoft Project ou Primavera P6 ?

Oui. L'application ouvre directement les fichiers .mpp (MS Project 2010 à 2021) et .xer de Primavera P6, sans le logiciel d'origine. MS Project XML, Primavera P6 XML, CSV et IFC s'ouvrent et s'exportent. L'application ne modifie jamais un .mpp ou un .xer : vous enregistrez en IFC.

Calcule-t-il comme P6 ou MS Project ?

Vous le choisissez avec le profil de calcul : Primavera P6, Microsoft Project ou Open Planner Studio. Un .xer s'ouvre avec le profil P6 et un .mpp avec le profil MS Project. Dates enregistrées affiche en plus les dates calculées par l'autre logiciel.

Dois-je installer quelque chose ?

Non. Toute l'application fonctionne dans le navigateur, avec ouverture, enregistrement, enregistrement automatique et récupération. Dans Chrome et Edge, Ctrl+S enregistre dans le même fichier ; dans Firefox et Safari, vous choisissez un fichier à l'enregistrement. Pour installer, il existe des versions Windows, macOS et Linux.

Combien coûte Open Planner Studio ?

Rien. L'application est gratuite et open source sous licence LGPL-3.0. Pas d'abonnement ni de licence par utilisateur.

Dans quel format mon planning est-il enregistré ?

En IFC 4.3, le standard ouvert de buildingSMART. Votre planning est un fichier IFC ; il n'y a pas de format propriétaire fermé. Vos données restent lisibles hors de l'application, et un logiciel BIM peut placer votre planning à côté d'une maquette pour une analyse 4D.

Sur quels systèmes fonctionne-t-il ?

Windows (.exe), macOS (.dmg universel, Intel et Apple Silicon) et Linux (.deb, .rpm, AppImage et snap). Et entièrement dans le navigateur.

Est-il adapté à la pratique du chantier ?

Oui. Vous créez des calendriers avec jours fériés, congés du BTP et horaires propres, et planifiez chaque tâche en jours ou en heures. Les ressources sont main-d'œuvre, matériel, matériaux ou sous-traitants, et les rapports sont faits pour les réunions de chantier et les clients.

Que peut faire un assistant IA avec mon planning ?

C'est facultatif et désactivé par défaut. Activez le mode IA dans l'application de bureau et un client IA comme Claude Code peut lire et modifier votre planning ouvert. Vous gardez la main : bouton pause, mode lecture seule, sauvegarde automatique avant la première modification et journal de chaque appel.

Technologie

Pour ceux qui veulent savoir comment c'est construit.

Tauri 2

Une fine couche native en Rust pour Windows, macOS et Linux. La même application tourne aussi en version web.

Moteur de calcul en TypeScript

CPM, calendriers, nivellement et profils de calcul tournent dans le navigateur comme dans l'application de bureau.

React 19 + TypeScript

L'interface, avec Zustand et Immer pour l'état et l'annulation. Construite avec Vite et Tailwind CSS.

HTML5 Canvas 2D

La chronologie du Gantt est dessinée sur un canvas ; la même routine produit l'impression et le PDF.

IFC 4.3 ADD2

Le format natif, écrit conforme au schéma ; IFC4 est aussi possible. Dans le navigateur, l'application utilise la File System Access API si elle existe.

Serveur MCP

Dans l'application de bureau, un serveur MCP intégré propose des outils planner_* à un client IA.

    This release makes MCP clients easier to connect, improves large-schedule performance, and hardens file handling, recovery and progress entry. Versions now use the ISO week-year, week and sequence (YYYY.W.N); the jump from 2026.10.0 reflects that numbering change.

    Added

    • Claude Desktop extension. A .mcpb asset connects Claude Desktop to the MCP bridge of the running desktop app. It forwards calls and contains no planner; the user supplies the token and port shown in the app.
    • Headless MCP server. The same 41 planner_* tools can run on Node without the desktop app, over stdio or authenticated loopback HTTP, in an isolated store context. File tools stay within a configured working folder, reject symlink escapes and save atomically without a direct-write fallback. The source build embeds the guides and examples it needs.
    • Desktop discovery files. The app writes bridge connection information and an inventory of open files for future MCP integrations. Documentation describes the identity and file-permission limits explicitly; the shipped Claude Desktop bundle still uses manual connection settings.
    • Arch Linux packaging. AUR packaging and its build/publication workflow accompany the existing desktop installers. Snap and AUR installations leave updating to their package managers.
    • AppImage desktop integration. Launching the AppImage writes a menu entry and icon in the user's data folder, respects existing entries it does not own and supports an opt-out.

    Changed

    • Large schedules. IFC reading indexes property relations, F5 computes outside the Immer producer, resource leveling reuses a forward pass when its prerequisites hold, and large leveling proposals render only visible rows. The full calculation fallback remains available.
    • Recovery serialization. Changed IFC snapshots are serialized by one reusable worker, with the existing writer as a fallback. Snapshot ordering, stopping and XER archive references remain guarded; file handles and archive bytes do not cross the worker boundary.
    • MCP naming. Ribbon controls, status, connection dialogs, settings and guides now call the external connection MCP. Tutorials use a movable guide panel without the former marking overlay.
    • Release automation. Weekly releases use explicit recovery, translation and CI gates, a deadline, reviewed fix PRs and successor versions when a failed tag needs changed source code.
    • Build inputs. Tailwind scans only application sources; Vite receives security updates.

    Fixed

    • Translation labels. Outdated or unhashed label translations no longer force an old UI name into a newly translated message. Once the label is current, exact label matching remains required.
    • Recovery and saving. Unreadable, invalid, duplicate or newer recovery manifests cannot trigger writes or cleanup of the refused recovery set. A blocked browser database upgrade completes startup with a persistent warning and requires reload before recovery accesses it again. Real web-save errors are reported, temporary export files are created exclusively, and MCP exports respect the document's file identity.
    • Scheduling and progress. External minute lags also apply to day tasks. Hour-task block boundaries, finish constraints, elapsed-time limits and deadline calendars receive targeted corrections. Reversed actual dates are refused; completed tasks without an actual finish retain the full scheduling path. Unknown driving status stays distinct from a known non-driving link.
    • IFC and imports. IFC phase progress and actual dates survive round trips, applying IFC editor content preserves document state and identities, and deep WBS structures avoid recursive open traversal. Building-model IFC files are refused before a lossy import. MSPDI escapes project date fields correctly; MPP import-loss reporting handles resource records, rates, notes, RTF and empty baseline dates more accurately.
    • Progress sheets. Invalid populated CSV dates are refused with row and field context; unmatched preview rows state their reason and source identifier.
    • Reports and editing. Report Print invokes PDF export, Backstage print preview opens the correct workspace, and PDF filenames follow the report language. Task calendars show names and offer a chooser; milestone creation and assignment feedback are consistent.
    • Help and updates. Pending actual-start questions survive Help navigation and freeze surrounding controls. Update preparation, installation and restart have separate phases, and automatic update dialogs wait until guided tutorials finish.

    Documentation

    • Updated Dutch and English guides for MCP, reports, recovery, calendar generation, conventions, imports, extensions and editing; refreshed README examples and tutorial references.
    • Updated the interface translations in all 28 languages through the translation pipeline. Guide translations beyond Dutch and English were not refreshed. Missing articles use the existing English fallback; older translations remain visible.
    • Refreshed wiki feature and installation pages, including the building-model guard and package manager update behavior.
