Écosystème OpenAEC

Architecture logicielle

Une seule base de code, toutes les plateformes. Nos outils fonctionnent en application web, en application de bureau sur Windows, Linux et macOS, et en application mobile — depuis le même code source.

Une seule base de code, partout

Chaque outil de l'écosystème OpenAEC est développé en tant qu'application unique fonctionnant sur toutes les plateformes. Pas de versions séparées web et bureau, pas de double maintenance. Le même code, les mêmes fonctionnalités, partout.

Nous y parvenons en construisant sur Tauri et Rust comme fondation, avec un frontend web moderne qui fonctionne à la fois dans le navigateur et dans un conteneur natif.

Stack technique

Tauri 2.0 Core

Framework pour construire des applications de bureau et mobiles avec des technologies web. Utilise la webview native de l'OS au lieu de Chromium — fichiers d'installation réduits (<10 Mo) et faible consommation mémoire.

Rust Backend

La logique métier de chaque outil est écrite en Rust : parsing IFC, validation, calculs et traitement de fichiers. Rust offre la sécurité mémoire, des performances élevées et compile pour toutes les plateformes.

WebAssembly Web

Le même code Rust compile vers WebAssembly (WASM) pour la version web. La logique de calcul complète tourne ainsi aussi dans le navigateur, avec des performances proches du natif.

TypeScript UI

L’interface utilisateur est construite avec des technologies web : TypeScript avec React ou Svelte, empaqueté avec Vite. La même interface fonctionne dans Tauri et dans le navigateur.

Three.js 3D

Visualisation 3D des modèles IFC via Three.js et That Open Engine. Basé sur WebGL, fonctionne partout où un navigateur fonctionne.

FastAPI API

APIs côté serveur construites avec Python FastAPI pour la validation asynchrone, la gestion documentaire et les intégrations. Déployées via Docker.

Local et dans le cloud — un seul système

Chaque outil OpenAEC fonctionne de façon autonome sur votre propre machine, sans connexion internet. Mais lorsque vous êtes en ligne, tout se synchronise de façon transparente avec le cloud via la plateforme OpenAEC. Projets, documents et données du modèle circulent automatiquement entre les installations locales et le serveur. À vous de choisir : entièrement local, entièrement dans le cloud, ou en configuration hybride.

Extensibilité & intégration

Les outils sont conçus pour être étendus et reliés. Quatre moyens, qui varient selon l’outil :

Open Feedback Studio Feedback

Un bouton de retour dans l’application, comme dans Open Safety Studio et Open 3D Viewer. Les utilisateurs signalent bugs et souhaits directement depuis l’application.

REST API API

Les outils avec un serveur, comme BIM Validator, BCF Manager Studio et OpenAEC Docs, proposent une API REST. Reliez-les à vos propres systèmes ou tableaux de bord.

MCP Servers AI

Model Context Protocol (MCP), entre autres dans Open Pointcloud Studio. Les agents IA (comme Claude) peuvent ainsi piloter l’outil directement en langage naturel.

Extensions Plugins

Des outils comme Open 2D Studio prennent en charge des extensions sur mesure, par exemple Drawing Statistics. Créez vos propres plugins en TypeScript ou Rust.

Open source

Construire sur des projets open source existants

Nous ne réinventons pas la roue. L'écosystème OpenAEC s'appuie autant que possible sur des projets open source éprouvés du monde du BIM et de la 3D :

  • That Open Engine

    Le rendu 3D et le parsing IFC dans nos visualiseurs reposent sur That Open Engine (anciennement IFC.js). Une puissante bibliothèque TypeScript/Three.js pour le BIM dans le navigateur.

  • Blender & Bonsai

    Pour la modélisation 3D et l'authoring BIM nous intégrons Blender et l'add-on Bonsai (anciennement BlenderBIM). L'outil 3D open source le plus puissant au monde.

  • IfcOpenShell

    La bibliothèque Python/C++ standard de l'industrie pour lire, écrire et manipuler les fichiers IFC. L'épine dorsale de notre traitement IFC côté serveur.

  • PDF.js & pdf-lib

    PDF.js de Mozilla pour le rendu et pdf-lib pour créer et éditer programmatiquement des documents PDF. Technologie éprouvée, des millions d'utilisateurs.

Pourquoi cette approche ?

Petit & rapide

Pas d'Electron, pas de Chromium. Tauri utilise la webview native — fichiers d'installation inférieurs à 10 Mo et consommation mémoire minimale.

Sécurisé

Rust prévient les erreurs mémoire, les buffer overflows et les race conditions. L'application est sécurisée par conception.

Open source

Tauri, Rust et toutes les bibliothèques utilisées sont open source. Aucun verrouillage propriétaire au niveau du framework.

Pérenne

Les standards web et Rust sont des technologies à longue durée de vie. Pas de churn de framework, pas de breaking changes.

OpenAEC

Logiciels open source pour toute la chaîne AEC (bâtiment, infrastructure, génie civil) — de la conception à la livraison et à la gestion.
