Sık sorulan sorular

Microsoft Project veya Primavera P6 dosyalarını açabilir miyim?

Evet. Uygulama .mpp (MS Project 2010–2021) ve Primavera P6 .xer dosyalarını orijinal program olmadan doğrudan açar. MS Project XML, Primavera P6 XML, CSV ve IFC açılabilir ve dışa aktarılabilir. Uygulama bir .mpp ya da .xer dosyasını asla değiştirmez: IFC olarak kaydedersiniz.

P6 veya MS Project gibi mi hesaplar?

Bunu hesaplama profiliyle seçersiniz: Primavera P6, Microsoft Project veya Open Planner Studio. Bir .xer P6 profiliyle, bir .mpp MS Project profiliyle açılır. Kaydedildiği gibi tarihler ayrıca diğer programın kendi hesapladığı tarihleri gösterir.

Bir şey kurmam gerekiyor mu?

Hayır. Uygulamanın tamamı tarayıcıda çalışır; açma, kaydetme, otomatik kaydetme ve çökme kurtarma dahil. Chrome ve Edge'de Ctrl+S aynı dosyaya kaydeder; Firefox ve Safari'de kaydederken bir dosya seçersiniz. Yine de kurmak isterseniz Windows, macOS ve Linux sürümleri var.

Open Planner Studio ne kadar?

Hiçbir şey. Uygulama LGPL-3.0 lisansıyla ücretsiz ve açık kaynaklıdır. Abonelik ve kullanıcı başına lisans ücreti yok.

Planım hangi dosya biçiminde kaydedilir?

buildingSMART'ın açık standardı IFC 4.3 ile. Planınız bir IFC dosyasıdır; kapalı, özel bir biçim yoktur. Verileriniz bu uygulamanın dışında okunabilir kalır ve BIM yazılımı planınızı 4D analiz için bir bina modelinin yanına koyabilir.

Hangi sistemlerde çalışır?

Windows (.exe), macOS (Intel ve Apple Silicon için evrensel .dmg) ve Linux (.deb, .rpm, AppImage ve snap). Ayrıca tamamen tarayıcıda.

İnşaat pratiğine uygun mu?

Evet. Resmî tatiller, inşaat tatili ve kendi çalışma saatlerinizle takvimler oluşturur, her görevi gün ya da saat olarak planlarsınız. Kaynaklar işçilik, ekipman, malzeme ya da taşeron olabilir; raporlar şantiye toplantıları ve işverenler için hazırlanmıştır.

Bir yapay zekâ asistanı planımla ne yapabilir?

İsteğe bağlıdır ve varsayılan olarak kapalıdır. Masaüstü uygulamasında yapay zekâ modunu açarsanız Claude Code gibi bir istemci açık planınızı okuyup düzenleyebilir. Kontrol sizdedir: duraklatma düğmesi, salt okunur mod, ilk değişiklikten önce otomatik yedek ve her çağrının günlüğü vardır.

    A large release: 2,165 commits (228 merged pull requests) since v2026.9.0. It opens Primavera P6 (.xer) files natively and makes the difference between P6, MS Project and Open Planner Studio calculation explicit through scheduling profiles; adds task types (fixed duration, units or work), task splitting, saved layouts, a progress sheet that round-trips through a spreadsheet, a resource diagram and seven new table reports (with a DCMA 14-point assessment); writes schema-valid IFC 4.3 ADD2 by default; ships the interface and the Help in 28 languages; replaces the Help with a Diátaxis-structured set of 78 articles; and prepares the product for the OpenAEC ecosystem with a headless core package, a headless HTTP API with a container and AWS definition, a release verification workflow and signed Windows programs. The features are backed by planning, library, MCP and browser regression coverage, including a fidelity measurement against P6's own calculated output and the 216-file .mpp corpus.

    Added

    • Open Planner Studio can now open Primavera P6 (.xer) files directly. A new, self-contained XER format layer reads the WBS, activities with duration, dates, constraints and progress, relations with lag, calendars, resources and assignments, activity codes, user-defined fields, notes and P6's scheduling settings (SCHEDOPTIONS). A Level-of-Effort activity becomes a hammock. A file with several projects opens one tab per project (the largest first); a project that P6 designates as another project's baseline becomes that project's baseline instead of a tab; cross-project links are preserved as source data. Documents are named "Project name (Project ID)". XER is read-only: the app never writes .xer and never changes the file.
    • Saving a document opened from XER keeps the original file inside the IFC. The complete .xer travels as a compact, verified source archive, so reopening the IFC still knows P6's own dates and settings. An unusable archive (damaged, or rewritten by another IFC program) no longer blocks opening: the project opens in full without the archive and a notice explains what is missing. Exports to CSV, MS Project XML and P6 XML state per format what XER source data they lose.
    • A new "Dates as recorded" view shows the dates the other package stored in the file. It applies to XER, P6 XML, MSPDI and .mpp (with the provenance carried through IFC, including the XER source archive): a strip under the ribbon says that you are viewing the schedule as recorded and how many tasks a recalculation would move, the Gantt keeps drawing relations, and the table marks values the file did not record instead of inventing them. Started and completed tasks always stay on their actual dates, as in P6. The view is offered only for formats that carry real calculated output, never for CSV or for an Open Planner Studio IFC without recorded provenance, and an IFC that you saved while in this mode opens in it again (a file saved after a recalculation opens with the calculation).
    • Scheduling profiles replace the old "if the source is P6" switch. One solver now runs three named profiles — Primavera P6, Microsoft Project and Open Planner Studio — each a set of conventions (27 in total, such as how P6 treats out-of-sequence completion, elapsed SS lags or the physical-completion point). Opening an .xer selects P6, an .mpp selects MS Project and everything else starts as Open Planner Studio; the engine itself no longer knows any file format. The profile and its project options survive IFC, crash recovery, MCP and the extension API (extension API 1.2.0).
    • Project settings has a Calculation profile block. Conventions are grouped by theme with the profile's base value shown per rule and a "back to base" action; built-in profiles are read-only, *New profile* saves your own app-wide template (each project keeps its own copy), and a block of deviating calculation options replaces the old *Standard options* button. Applying the block is one undo step and is guarded against unapplied changes.
    • Primavera-faithful calculation was measured against P6's own output. The first measurement showed 15,056 six-axis date deviations against the P6-calculated files; the conventions above, together with an agreed oracle population (only files P6 itself calculated), reduce this to 76, guarded by a ratchet that can only go down, and a measure:profiles gate that no exact cell may become inexact when engine behaviour changes.
    • Task types link duration, units and work per task. The task types are Fixed duration and units, Fixed duration and work, Fixed work and Fixed units, as in MS Project's Task Type and P6's Duration Type; the app shows task type and work once the setting *Use task types* is switched on. Changing a duration, units, the work, the resource or the calendar goes through one bridge that keeps the stored work coherent, including contours, started tasks and the calendar-switch case. The task type has its own drop-down with an explanatory info icon per option, the task grid shows a *Task type* column, and stored work that deviates from units × duration is marked.
    • P6 and XML files keep P6's remaining work rate. For work still to be done the app now uses and shows the remaining rate (remain_qty_per_hr, RemainingUnitsPerTime) and keeps the planned rate separately (*Planned units per day*), so a Foreman assignment shows 34 instead of 1.11 next to 306 h of remaining work, and a duration change gives the same work as in P6.
    • Tasks can now be split by the user. A split mode in the ribbon cuts a bar at a date in the Gantt; pieces and piece edges can be dragged, interruptions can be removed from the context menu, and the properties panel has an *Interruptions* section. The leveler never cuts a task that has its own interruptions, completed work is protected, and exporting to MSPDI or P6 reports that interruptions are lost. The MCP tool planner_set_task_splits offers the same.
    • Layouts: every saved view is a ribbon button. A layout stores only what it contains — filter, grouping, sorting, task-table columns, time scale and the overlay group (relation lines, baseline, progress line, status date line, resource accent, float band, bar colours). Clicking a button toggles it on and off with a restore point, each click is one undo step, a *New layout* dialog with checkboxes and info tooltips defines parts, and the built-in layouts *Gantt (WBS)* and *Resource diagram* ship with the app. Saved filters now live inside layouts.
    • A warnings panel lists schedule rule failures and navigates to the task, relation or resource concerned (issue #53).
    • The progress sheet round-trips through a spreadsheet. *Export progress sheet* writes a slim sheet — as CSV or as a real .xlsx with column widths, frozen headers, input validation and instructions in the column headings — and *Import progress* reads it back from three entry points: a preview plan matches rows by override, ID or WBS, shows exactly what would change, and applies it atomically. Phases mark themselves in the sheet, ambiguous dates and percentages get specific reasons, and the sheet never appears in the recent-files list. The .xlsx reader and writer, with their own ZIP and XML handling, have no external dependency (issue #27).
    • Progress entry follows consistent rules everywhere. Entering progress without a status date sets the status date to today (local day) with a notice; progress on a task that, per plan, starts after the status date asks for the actual start; lowering the duration of a running task below the work already done is refused, otherwise the done work stays and remaining duration and percentage follow. The same rules apply in the panel, the context menus, the grid, *Edit task*, the progress import and the AI assistant. Phase progress and actual dates are derived from their leaf tasks and read-only.
    • A resource diagram report prints the Gantt per resource, one sheet per person. It groups by resource and resource type in two layers, shows units per day and the contour/curve per row, supports a reporting period and weekly or monthly grouped load, repeats a legend footer on every page, drops the assignment columns when they would leave too little timeline, and can be exported as PDF.
    • Seven table reports arrived with discussion #31: look-ahead, critical and near-critical, progress, schedule health, resource loading, resource assignments and WBS summary, plus a shared reporting period. Schedule health now starts with the DCMA 14-point assessment according to EVMS Program Analysis Pamphlet DCMA-EA PAM 200.1 (count, total, value, threshold, result and detail per point; a flag is a reason to look further, not a failure).
    • Work distribution per day is now data, and can be edited. Contours are native in MSPDI and P6, the properties panel edits the hours distribution per assignment with a draggable phase strip and phase table instead of day rows, and *Double peak* and *Turtle* are full curves.
    • Resource overallocation now explains itself. A day on which a resource is overbooked shows the reason (for example a day off in the resource calendar) in the histogram and in the warnings; the histogram resource picker scrolls with a pinned total row, and short hour tasks now carry their load into the histogram, overallocation and leveling.
    • The leveling dialog calculates in the background and can be stopped. Long leveling runs no longer freeze the interface.
    • IFC files declare and keep their schema. New projects are written as IFC 4.3 ADD2 (the schema of IfcOpenShell and Bonsai); Project settings offers IFC 4.3 or IFC4 for saving, and a file with another schema asks once at the first save whether to keep it. Undo, extensions, export and planner_export_ifc never change the schema silently. This makes IfcOpenShell MergeProjects work with IFC4 and IFC 4.3 models (issue #292). A newly written file loses calendar data when it is opened in an older app version (see Changed).
    • Time notation setting. Clock times show in 24-hour or 12-hour notation (default 24-hour) in the calendar dialog, date-time cells, split labels, the Gantt hour scale, notices and dialogs; storage, files and MCP stay ISO 24-hour. Midnight is 24:00 / 12:00 AM, a night block such as 22:00–06:00 is written as "next day", and the input accepts 13, 1300 and 1 pm.
    • The status date now has a time, and you can see and change it. In a project whose calendar works in hours, the ribbon (Planning, Baselines & progress) shows a time field next to the status date, the status date line in the Gantt and in print stands at that moment, its label reads 20-09-2006 17:00 in your date and time notation instead of raw ISO, and the progress line compares "done" and "not started" at that moment instead of per day. Two files with status dates 12:00 and 17:00 no longer look the same while the remaining work differs by half a day. A day-based calendar shows no time field and behaves as before, because the solver ignores the time there (isHourModeCalendar, one test shared by ribbon, renderer, print and solver).
